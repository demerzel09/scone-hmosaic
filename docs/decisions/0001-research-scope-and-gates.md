# ADR-0001: 初期文書と研究ゲート

- 日付: 2026-10-04（Asia/Tokyo）
- 状態: 採用（初期文書の構成と作業範囲）
- 根拠: [RESEARCH_SPEC.md](../../RESEARCH_SPEC.md)、ユーザーの「まず把握して、readme.md と初期文書を整備して、その後 push」という依頼。

## Observation

開始時の作業ツリーには未追跡の `RESEARCH_SPEC.md` だけがあり、commit はなかった。仕様書は M1 の実装を最初の研究作業とする一方、今回の依頼はその前の理解と文書整備である。

仕様書 §31 のロードマップ番号と §33–§35 の段階見出しにはずれがある。実 SCONE の導入、API、出力形式、初期 scenario は未確認である。

## Decision

1. 仕様書原本は変更せず、初期 commit に含める。
2. 依頼の表記に合わせて root の入口を `readme.md` とする。仕様書 §26 の `README.md` に対応する文書であり、重複ファイルは作らない。
3. 研究計画、仮説、構成、実験規約、データ契約、AGENTS、初期状態の報告を整備する。
4. 最初の実験 YAML は `draft` とし、API・scenario・許容差が決まるまで実行不可とする。
5. 段階参照は §31 のロードマップ番号に作業名と該当節を添える。原本の番号を改訂しない。
6. 今回はコードや実験結果を作らない。次の実装は §32・§43 の M1 に限定し、完了後は報告して停止する。
7. SNN と局所可塑性の前に共有モジュールの Go / No-Go を行い、No-Go なら人間のレビューを待つ。

## Evidence

仕様書 §1・§18・§32・§36・§42・§43 と開始時の repository 状態。研究実験による証拠はまだない。

## Consequences

初期文書から次の作業と停止条件を追える。未実装 component や YAML 草案を、実行済み成果物と誤認しない。成功基準の数値と SCONE integration の詳細は実装前の確認事項として残る。

## Revisit if

ユーザーが研究仕様や作業範囲を変更した場合、番号体系を整理する場合、または SCONE integration の実調査で設計変更が必要になった場合。科学的判断は別 ADR に証拠を添えて記録する。
