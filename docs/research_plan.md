# 研究計画

基準: [RESEARCH_SPEC.md](../RESEARCH_SPEC.md) §1・§31–§43。

## 目的と最初の判断

保存した予測・制御モジュールの選択、再結合、局所修正が、継続学習や少量適応に有効かを検証する。最初の判断は、複数条件の運動を少数の共有モジュールで説明できるかである。

初期の局所線形モデルは、この前提を低い実装コストで反証可能にするために用いる。単一軌跡で予測誤差が減っただけでは、共有モジュール仮説を支持したことにしない。

継続学習の評価設計と小さな比較実験は早期に準備する。SNN 置換前にも、通常モデルで再利用・継続学習・階層化の成立を確認する。後半の番号を理由に、これらの証拠を先送りしない。

## 次の実装範囲: M1

1. SCONE の実行方法、エンジン、バージョン取得、seed の指定方法を一次資料と実環境で確認する。
2. 既知の歩行シナリオを選び、モデル・外部ファイルの依存関係と配布条件を記録する。
3. Python プロジェクト、ExperimentSpec の入力検証、run 保存を作る。
4. runner でシナリオ・seed・出力先を指定し、実行コマンド、終了コード、stdout/stderr を保存する。
5. 実出力を調査し、データ契約に沿った parser と変換を実装する。
6. 最小可視化、unit/integration の検証、実 SCONE の反復実行を行う。
7. `docs/status/milestone_1_report.md` に実装、再実行方法、テスト、未解決点をまとめる。

SCONE が利用できない間も、入力検証、run 保存、失敗処理、fixture を使った parser は実装可能。ただし mock の成功を実 SCONE の実行成功や科学的証拠として報告しない。

## M1 の受け入れ条件

- 固定 seed、scenario、engine、version を記録して実行できる。
- 実際の歩行シナリオから標準軌跡を生成し、schema 検証に通る。
- 同一条件・同一 seed の反復が、実行前に固定した許容差で等価になる。
- SCONE の失敗を非ゼロ終了として呼び出し元へ伝え、両ログを保存する。
- unit test が通り、実 SCONE の integration test の実行結果がある。
- §28 の run 記録と §32 の軌跡・metadata が保存される。
- 実装報告を作成したら停止し、次段階への明示的承認を待つ。

## 最初の Go / No-Go

M4 で少なくとも次を同じ評価集合で比較する。

- 複数条件を共有モジュールで表現する方法。
- 1 個の global model。
- 条件ごとに独立した model。

予測誤差、controller 再現誤差、モジュール数、パラメータ数、複雑さ指標、条件間再利用を、未学習 episode と held-out 条件で評価する。精度・共有率・複雑さの数値基準は、独立 pilot 後、評価結果を見る前に YAML に固定する。

判定は `Go`、`No-Go`、`inconclusive` を区別する。Go は事前基準を満たす場合、No-Go は必要な証拠が揃ったうえで共有仮説が支持されない場合、inconclusive はデータ不足や実装不備で判断できない場合とする。

No-Go の場合は状態表現、粒度、非線形局所モデルの必要性、仮説修正を報告して人間のレビューを待つ。SNN や局所可塑性へ自動的に進まない。

## 未確定事項

- SCONE/Hyfydy の導入、使用可能なエンジン、実行 API、出力形式。
- 使用モデルと初期シナリオ、計算資源、データの保存場所。
- 状態・行動の特徴量、単位、サンプリング周期。
- pilot と評価条件、再現性の許容差、Go / No-Go の数値基準。

確定時は実験仕様または ADR に根拠を残す。現時点で日程や結果は確定しない。
